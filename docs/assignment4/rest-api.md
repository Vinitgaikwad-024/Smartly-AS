# Assignment 4 — Contract-First REST API

`../../openapi.yaml` is the OpenAPI 3.0.3 contract. The implemented resource model uses nouns in paths: `/rooms`, `/bookings`, and `/admin/rooms`. State-changing operations use HTTP methods or explicit transition subresources (`/approve`, `/reject`, `/cancel`).

## Resource operations
- `GET /rooms`: filters (`building`, `type`, `minCapacity`) and pagination (`page`, `limit`).
- `GET /rooms/{room_id}`: details, ETag and conditional GET.
- `POST /bookings`, `GET /bookings`, `GET /bookings/{booking_id}`.
- `POST /bookings/{booking_id}/cancel|approve|reject`.
- Admin room inventory: GET/POST `/admin/rooms`, PATCH/DELETE `/admin/rooms/{room_id}`.

Booking create is protected by a demo Bearer token and accepts `Idempotency-Key` to replay the original 201 result. Errors use Problem Details. The project includes `models.py`, `store.py`, and `errors.py` as explicit coursework layers alongside `app.py` and `tests/`; see their module documentation. The prototype is in-memory, not production persistence.

## Outbound integration
`services/notification_client.py` uses finite timeout, bounded attempts, exponential backoff plus jitter, retries transport errors and 5xx, and does not retry partner 4xx. The SOAP partner is fictional. Do not describe a live notification as delivered; the adapter is tested with a fake session.
